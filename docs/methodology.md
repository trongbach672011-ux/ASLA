# Benchmark methodology

The benchmark changes one component: attention. Everything else is held as close as practical across the paired runs.

## Training setup

| Setting | Value |
|---|---:|
| Device | Tesla T4 |
| PyTorch | 2.10.0+cu128 |
| Precision | FP16 AMP |
| Vocabulary | 32,000 |
| `d_model` | 224 |
| Layers | 4 |
| Query heads | 4 |
| Head size | 56 |
| Sequence length | 256 |
| Batch size | 8 |
| Steps | 2,000 |
| Tokens/run | 4,096,000 |
| Optimizer | AdamW |
| Learning rate | 3e-4 |
| Weight decay | 0.01 |
| Grad clip | 1.0 |
| Seeds | 1234, 2025, 3407 |

The total parameter counts are 9,278,304 for ASLA-P1 and 9,278,328 for MLA. That is a `0.000259%` difference.

The paired runs reuse the same data order, optimizer budget, batch/step schedule, RoPE frequency profile and common backbone initialization scheme. Eval CE is reported without ASLA-P1's auxiliary routing/basis penalty.

## Dataset

`data/realdata_cache.pt` is a deterministic synthetic LM dataset generated by `scripts/build_benchmark_cache.py`.

It mixes a few patterns that are useful for a small attention proxy:

- nonlinear local recurrence;
- repeated/copy spans;
- key-value definitions near the start of a sequence;
- later retrieval queries for those definitions.

There are 3,584 training rows and 512 evaluation rows. Each row has 257 tokens; the language-model input and target are produced by shifting that row by one token.

This dataset is useful for controlled iteration. It is not meant to stand in for broad natural-language or code evaluation.

## Metrics

### Quality

`eval_loss` is mean token cross-entropy. Perplexity is `exp(eval_loss)`. Next-token accuracy uses exact argmax matching. Copy-span accuracy measures the synthetic repeated-token task.

### Training behavior

The repo reports tokens/second, p50/p95 step time, peak allocated VRAM, and the standard deviation of cross-entropy near the end of training (`tail_ce_std`). Lower tail variation is treated as a stability signal, not as a standalone quality metric.

### Attention-only prefill

The frozen latency sweep runs sequence lengths `64, 128, 256, 512, 1024, 2048` at batch size `2`. Each point uses 10 warmup iterations and 30 measured repeats. The radar uses p50 latency at sequence length `2048`.

This test measures prefill. It does not measure autoregressive token-by-token decode with a persistent KV or latent cache.

## Cache accounting

The repo keeps current materialized memory and analytical compressed-state accounting separate:

| Architecture | Current/materialized path | Analytical compressed path |
|---|---:|---:|
| ASLA-P1 | 224 el/token/layer | 44 el/token/layer |
| MLA | 448 el/token/layer | 93 el/token/layer |

The radar uses `44` and `93` on the cache axis, so that axis is explicitly theoretical.

A smaller analytical state should not be converted directly into a wall-clock speed claim. FlashAttention and FlashAttention-2 are good examples of why: IO behavior, occupancy, work partitioning and kernel structure can change runtime substantially without changing the mathematical attention result.

## Radar normalization

With only two models, ordinary min-max scaling is a poor fit because any nonzero difference becomes `1` versus `0`.

For lower-is-better metrics:

\[
score_i=\frac{\min_j x_j}{x_i}
\]

For higher-is-better metrics:

\[
score_i=\frac{x_i}{\max_j x_j}
\]

The best model on an axis gets `1.0`; the other retains the size of the relative gap.

## Reading the three-seed result

The paired eval-loss deltas `(ASLA - MLA)` are:

| Seed | Delta |
|---:|---:|
| 1234 | +0.00116 |
| 2025 | -0.45094 |
| 3407 | -0.00224 |

The mean is therefore sensitive to seed `2025`. Two runs are near ties. More paired seeds are needed before treating the quality difference as robust.

For a follow-up intended to support a stronger claim, I would increase the number of seeds first, then move to a larger model and a real corpus, and finally add an optimized autoregressive decode benchmark for both cache designs.
